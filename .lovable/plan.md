# Automatic SKU Generation

## Goal
Every product/service gets a unique, readable, immutable SKU generated by the system — no manual typing, no duplicates, no blanks.

## Format
```
PRD-BEN-APP-DRVCOV-7K2      product
SVC-GLB-COA-JUNIOR-4M9      service
```
- Segment 1: `PRD` (product) / `SVC` (service)
- Segment 2: 3-letter city code, `GLB` when the item is global (no city)
- Segment 3: 3-letter category code (from the category name; `OTH` fallback)
- Segment 4: up to 6 chars from the item name (letters/digits only, uppercased)
- Segment 5: 3-char base36 uniqueness suffix

Uniqueness comes from the suffix, so two items with identical name/city/category never collide. Everything before it exists purely for human readability in exports and reports.

## Rules
- Generated server-side by a database function so the app, the CSV importer, and any future automation all produce identical SKUs.
- **Immutable once set.** A city or category change does not rewrite the SKU — internal joins use the product UUID, so a stale prefix is cosmetic, and rewriting SKUs would break customer-facing history and printed labels.
- Admin UI shows the SKU read-only with a "Regenerate" action, used only for genuine mistakes.
- Database enforces uniqueness so nothing can slip through a second path.

## One-time backfill
1. Add the uniqueness rule to the SKU column (safe: nothing internally joins on SKU).
2. Rewrite every existing SKU in the new format, including the 13 blank global services and the 4 duplicated codes (Drink, MZ W Grip Glove, JN Junior Glove, JN Golf Gloves).
3. Keep the previous code in a `legacy_sku` column so any old spreadsheet or printed label can still be traced. It is display-only and never written again.

## Technical notes
- New migration: `generate_sku()` DB function + `BEFORE INSERT` trigger on `products`, unique index on `sku`, `legacy_sku` column, idempotent backfill `UPDATE`.
- `src/components/admin/ProductForm.tsx`: remove the client-side `generateSKU()` helper, drop `sku` from the insert payload, render the field read-only for existing rows.
- CSV importer: match rows on SKU; blank SKU means a new row and gets one generated.
- Tests: format correctness, uniqueness under duplicate names, immutability on update, backfill idempotency.

## Why this is low tech debt
One generator, in one place, owned by the database. No client/server drift, no duplicate-SKU import failures, and no rename cascade because SKUs are never rewritten after creation.
